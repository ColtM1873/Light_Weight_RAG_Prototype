# 01 · 需求说明

## 1. 背景与用户

公司制度、FAQ、产品手册散落在多个文档中，员工需要快速找到**有依据**的答案。普通 RAG 的两类高风险失败是：

1. **引用不实**：声称“根据某文档”，但原文片段不存在或不属于该文档；
2. **过度断言**：检索结果不足以支撑结论，模型仍给出确定答复。

目标用户是公司员工（差旅、薪酬、招聘、IT/信息安全、CRM 等场景），他们需要的是“能点回原文的答案”，而不是一段听起来合理的文字。

## 2. 目标

用一份可运行的最小项目证明：

- 能检索带文档 ID、版本日期的合成制度/FAQ，并给出**回答 + 引用文档 ID + 原文片段 + 资料缺口 + 任务状态**；
- 模型能根据工具结果动态决定：补充检索、读全文、查版本日期、追问或停止；
- 文档冲突时列出冲突双方，不擅自选一个答案；
- 资料不足 / 资料外问题时明确说明缺口，不编造；
- 工具失败时能换查询/换工具，仍失败则如实说明；
- 有执行步数上限，达到上限返回明确的未完成状态；
- 用至少两条执行路径的 Trace 证明上述行为，并覆盖全部验收点。

## 3. 范围

### 3.1 范围内

- 8 份合成企业文档（差旅报销制度/FAQ、年终奖章程、云办公手册、招聘入职制度、薪酬福利 FAQ、CRM 手册、信息安全制度）；
- 文档扫描、ID 分配、版本日期解析、分句/分块、FAISS 向量索引；
- LangGraph 主图：Model A 工具循环 + Guard 1（结构化抽取 + 代码引用校验）+ Guard 2（证据支持性判定）+ finalize（最终整理）；
- HTTP API + SSE 浏览器演示；CLI 演示与 Trace 生成；
- 离线 Mock 入口（无 API key 时验证流程）；
- 单元测试与集成测试；
- 浏览器会话自动落盘（`Chat-History/`）。

### 3.2 范围外

- 生产部署、鉴权、多租户、速率限制、可观测性平台；
- PDF/Word 解析、OCR、复杂版式；
- 多 Agent 协作、长期记忆、跨会话用户画像；
- 前端框架化、Markdown 渲染、移动端适配；
- 真实企业数据接入（本项目只使用合成数据）。

## 4. 输入与输出

### 4.1 输入

- 用户问题（可带对话历史；同一 `thread_id` 即多轮上下文）；
- `data/ref_files/` 下的 `.md` / `.txt` 文档，文件名 `Dxxx_标题.md`，首行可写 `版本日期：YYYY-MM-DD`。

### 4.2 输出

- 自然语言回答；
- 引用：`document_id` + 原文片段（不要求片段定位 ID）；
- 资料缺口；
- 任务状态：`done` / `conflict` / `no_support`；
- 执行路径：每步节点、工具参数、工具返回摘要/全文、Guard 判定、最终状态。

## 5. 必须验收点与对应材料

| 验收点 | 期望行为 | 对应案例 |
|---|---|---|
| 明确答案 | 文档完全支持时给出明确结论 + 引用 | `examples/cases/01-explicit-answer.md`、05、06、07 |
| 文档冲突 | 列出冲突双方原文与版本，请用户确认，不擅自选边 | `02-conflict-followup.md`、`04-paraphrase.md` |
| 资料外问题 | 明确说明库中没有相关资料，不编造 | `03-no-support.md`、`08-policy-gap-followup.md` |
| 改写后的相似问题 | 换一种说法仍能检索到同一批文档并识别冲突 | `04-paraphrase.md` |
| 上下文追问 | 同一会话内结合上一轮继续回答 | `02`、`05`、`08` |
| 工具失败 | 工具报错后换查询/换工具；仍失败则如实说明 | `06-tool-failure.md` |
| 替换文档内容 | 文档改内容后同一问题答案随之改变 | `07-doc-replacement/`（350 → 600 元/晚） |
| 引用支持回答 | Guard 1 逐条校验引用原文；Guard 2 判定支持性 | 所有在线案例的 `guard_parse` / `guard_support` 事件 |
| 步数上限 | 达到上限返回明确的未完成状态 | `MAX_STEPS=100`；单测 `test_step_limit_returns_incomplete_status` |
| 至少两条执行路径 | 记录模型根据工具结果调整动作 | 01（检索→作答）、02（多轮冲突）、04（冲突识别）、06（失败→换查询）、07（内容变化） |

## 6. 成功标准

- 能按 README 的命令从零启动（安装依赖、配置 `.env`、`python run.py serve`）；
- 44 个测试全部通过；
- `examples/` 至少 3 组输入/输出/Trace，且覆盖上表全部验收点；
- Guard 1 / Guard 2 在每条在线 Trace 中都有可核对的结构化结果；
- 所有路径（包括两个 Guard 一次通过）都经过 `finalize`，最终答复是整理稿；
- 文档替换实验前后数据可恢复，仓库最终提交原始数据；
- `.env`、真实密钥、浏览器原始历史不进入提交。

## 7. 假设与边界

- 文档为合成资料，不含真实个人信息或商业机密；
- 问题假设用户愿意在文档范围内讨论；纯闲聊问题可能被 Guard 要求补引用（见 03 评估的已知限制）；
- 模型效果依赖 `deepseek-chat` 的当前版本；项目提供离线 Mock 只验证流程，不证明真实决策效果；
- 向量模型需要本机 HF 缓存；没有缓存时可按 README 联网下载。
