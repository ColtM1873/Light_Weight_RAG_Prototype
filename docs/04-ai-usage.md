# 04 · AI 使用说明

> 本文如实记录本次项目中 AI 辅助的范围、人工负责的部分，以及验证方式。
> AI 只作为编码/文档助手，不替项目作者做业务与验收决定；所有结论以实际运行结果为准。

## 1. 使用的 AI 工具

- AI 编码助手（DeepSeek Harness 会话中的 Agent）：用于仓库重组、代码重构、测试补充、文档初稿、Trace 生成命令。
- 大模型 API：`deepseek-chat`，用于运行时回答与两道 Guard 的判定（这是项目功能的一部分，不是“开发时作弊”）。
- 未使用 AI 生成真实企业数据；`data/ref_files/` 是合成资料。

## 2. AI 辅助范围

| 范围 | AI 参与内容 | 人工把关 |
|---|---|---|
| 仓库重组 | 把平铺脚本拆成 `src/knowledge_agent/` 包，迁移 `data/`，统一 `paths.py`，更新导入/启动脚本 | 确认目录符合考核规范、运行命令可用 |
| RAG 管线 | 懒加载资源、相对路径、会话隔离、上下文窗口修复、FAISS 中文路径处理 | 确认检索结果与文档一致 |
| Guard 层 | 保留/整理 Model B/C prompt、引用校验、反馈话术、finalize 必经逻辑 | 决定“冲突不擅自选边”“最终整理必须加”等产品规则 |
| Trace / 历史 | 设计 `TraceRecorder`、`Chat-History` 落盘、Guard/状态卡的 SSE 事件 | 决定浏览器里要看到哪些结构化内容 |
| 示例 | 生成在线 Trace、工具失败注入、文档替换对照实验、离线 Mock | 审阅最终答复、确认案例覆盖验收点 |
| 文档 | README、docs/01-05、examples 索引初稿 | 校对事实、数字、限制与措辞 |
| 测试 | 补充 RAG/历史/Trace/步数上限测试 | 运行并确认 44 passed |

## 3. 个人贡献（项目作者）

按项目实际协作方式，以下部分由人工负责或最终拍板：

- **业务与资料**：确定“企业知识问答 Agent”题目，准备 8 份合成制度/FAQ 文档与验收问题；
- **方案取舍**：
  - 双 Guard 分工：确定性引用校验交给代码，支持性判断交给 LLM；
  - 文档冲突时列出双方、请求用户确认，不擅自选边；
  - 引用只要求 `document_id + 原文片段`，不暴露内部 `piece_id`；
  - **所有 Guard 通过路径都必须 finalize**（2026-11-14 明确要求）；
  - 浏览器必须显示 Guard 判定和结构化任务状态；
- **验收与改进**：实际在浏览器提问，指出“看不到任务状态 / 不知道 Guard 是否运行 / Chat-History 为空”等问题，推动补齐结构化记录与状态卡；
- **场景委托**：指定“工具失败”“替换文档内容”两个场景由 AI 构造，并审阅结果。

## 4. 验证方式

| 验证项 | 命令/方式 | 结果 |
|---|---|---|
| 静态检查 | `python run.py check` | 配置、数据、索引、hash 均正常 |
| 单元/集成测试 | `pytest tests -q` | 44 passed |
| 在线 Trace | `python run.py ask ...` | 8 个案例全部生成 JSON/Markdown |
| 浏览器 SSE | `python run.py serve` + 实际提问 | Guard 卡、状态卡、finalize、Chat-History 均出现 |
| 工具失败 | `--fault-tool query_the_docs --fault-times 1` | 首次失败 → 换查询成功 → 作答 |
| 替换文档 | 修改 D001 → 重建索引 → 同问题重跑 → 恢复 | 350 → 600；恢复 SHA256 一致 |
| 离线 Mock | `python run.py demo --case ...` | 4 个场景跑通，明确标注边界 |

## 5. AI 输出的边界与人工复核

- AI 生成/改写的代码都经过运行测试；测试失败时以实际错误为准修改，不直接采信“看起来对”的代码。
- AI 生成的文档数字（测试数、文档数、句子数、chunk 数、SHA256）均来自实际命令输出。
- 在线 Trace 是真实 API 运行结果，但模型本身有随机性；同一问题重跑可能措辞不同。
- 离线 Mock 的回复是预设脚本，只验证流程/工具接线，**不能证明真实模型决策效果**。
- 没有把模型内部思维过程写入 Trace；只记录可观察的输入、工具参数、工具返回、Guard 结构化结果和最终答复。

## 6. 对“AI 辅助”的反思

- AI 很擅长做重复性重构（移动文件、改导入、补测试、写索引），但**业务规则与验收口径必须由人拍板**；例如“一次过是否 finalize”就是产品决策，不是代码问题。
- 本轮最大的教训是“可观察性”不是附加项：Guard 在后台通过，但界面/记录不可见，用户就会合理怀疑它没运行。后续应把“结构化状态可见”作为 Guard 的一等需求。
- AI 生成的示例需要人工核对是否真的覆盖验收点；仅凭“跑通了”不等于“证明效果”。
